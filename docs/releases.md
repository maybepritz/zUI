# Именованные релизы zUI

Текущая подготовка: **0.3.2 Altair** (исправления к 0.3.0). Первый выпуск назывался Lyra (созвездие Лиры),
второй — Vega, по её самой яркой звезде, третий — Altair, соседняя вершина Летнего
треугольника. Для крупных обновлений берём короткие
названия звёзд и созвездий. Это имя релиза, а не отдельная редакция приложения.

## Номер и имя

- Числовая версия задаётся в корневом `Cargo.toml`, в `workspace.package.version`.
- Имя задаётся в `crates/app/release-name.txt`.
- `app/src/release.rs` объединяет их для окна, бокового меню и экрана изменений.
- Windows FileDescription также содержит номер и имя.
- Автообновление и last_seen_version используют только числовую версию.

Исправления внутри одного выпуска сохраняют имя: например, `0.3.1 Altair`. Экран изменений при таком обновлении не показывается: он сравнивает версии без последнего числа.
Следующее крупное обновление получает новый номер и имя, например `0.4.0 Deneb`.
Это примеры схемы, не утверждённый график будущих релизов.

Для текущего выпуска:

| Поле | Значение |
| --- | --- |
| Git-тег | `v0.3.2` |
| Заголовок GitHub Release | `zUI 0.3.2 Altair` |
| ZIP для Windows | `zUI-x86_64-pc-windows-msvc.zip` |
| Файлы внутри ZIP | `zUI.exe`, `LICENSE` |

Не добавляйте имя к Git-тегу, Cargo-версии или имени исполняемого файла.
Номер должен оставаться пригодным для сравнения автообновлением; архив содержит
target, который использует GitHub-updater.

## Перед публикацией

Сборку, clippy, тесты и проверку переводов на каждый пуш в `main` выполняет
GitHub Actions (`.github/workflows/ci.yml`). Вручную остаётся проверить в приложении:

- [ ] Первый запуск из чистой папки и запуск с настройками от 0.2.0.
- [ ] Экран запуска: ленты сходятся в логотипе, итог проверки обновлений, вопрос о правах без администратора.
- [ ] Главная: переключатель обхода, плашка про права, график «Час» и «Сутки» с пропусками.
- [ ] От администратора: «Запускать вместе с Windows» создаёт задачу «zUI Autostart», после входа в Windows обход включается без UAC; выключение убирает задачу.
- [ ] Снять zUI через диспетчер задач при работающем обходе: winws.exe и прокси Telegram исчезают.
- [ ] Повторный запуск показывает уже открытое окно, в том числе скрытое в трей.
- [ ] С применённым DNS и автозапуском: `zUI.exe --cleanup` возвращает прежние серверы и убирает задачу.
- [ ] Окно не разворачивается на весь экран ни кнопкой, ни двойным щелчком по заголовку.
- [ ] Подбор: после мастера и по «Подобрать заново» — ход на главной, отмена, обход включается сам.
- [ ] «Проверить сейчас» на главной.
- [ ] Скрытие в трей, открытие из трея, выход и оба запоминаемых действия.
- [ ] Экран изменений: RU/EN, светлая/тёмная тема, минимальный размер окна.
- [ ] Установка/запуск Zapret и Telegram, тестирование стратегий и изменение/восстановление DNS.
- [ ] Обновление с предыдущего релиза из архива с указанным именем и структурой.
- [ ] В архиве есть LICENSE и нет runtime, настроек, журналов, секретов и отладочных символов.

## Сборка и публикация

Релиз собирается сам (`.github/workflows/release.yml`): когда в `main` попадает
коммит с новой версией в `Cargo.toml`, GitHub собирает ZIP, ставит тег
`v<версия>` и создаёт черновик GitHub Release с архивом. Заголовок
(`zUI <версия> <имя>`) и текст черновика берутся из раздела `## <версия>` в
[CHANGELOG](../CHANGELOG.md): если раздела нет, сборка остановится до создания тега.
Если тег уже есть, ничего не происходит. Проверьте черновик и файлы и опубликуйте.
Повторить сборку можно кнопкой Run workflow на вкладке Actions.

Собрать архив вручную, без GitHub, можно в PowerShell из корня проекта:

```powershell
cargo build --release --locked --target x86_64-pc-windows-msvc -p zUI --bin zUI
New-Item -ItemType Directory -Path dist -Force
Compress-Archive -LiteralPath @('target/x86_64-pc-windows-msvc/release/zUI.exe', 'LICENSE') -DestinationPath dist/zUI-x86_64-pc-windows-msvc.zip -Force
```

## Следующий выпуск

1. Измените числовую версию и при необходимости имя.
2. Синхронизируйте версии workspace-пакетов в Cargo.lock.
3. Обновите `whats-new-summary`, `whats-new-footer` и `whats-new-notes` во всех языках.
4. Сохраните формат заголовков `##` и пунктов `-` для карточек экрана изменений.
5. Обновите README, CHANGELOG и этот документ.
6. Выполните проверки выше и запушьте в `main`: черновик релиза появится сам.
