# Именованные релизы zUI

Текущая подготовка: **0.1.0 Lyra**. Lyra — Лира; для крупных обновлений используем
короткие названия созвездий. Это имя релиза, а не отдельная редакция приложения.

## Номер и имя

- Числовая версия задаётся в корневом `Cargo.toml`, в `workspace.package.version`.
- Имя задаётся в `crates/app/release-name.txt`.
- `app/src/release.rs` объединяет их для окна, бокового меню и экрана изменений.
- Windows FileDescription также содержит номер и имя.
- Автообновление и last_seen_version используют только числовую версию.

Исправления внутри одного выпуска сохраняют имя: например, `0.1.1 Lyra`.
Следующее крупное обновление получает новый номер и имя, например `0.2.0 Vela`.
Это примеры схемы, не утверждённый график будущих релизов.

Для текущего выпуска:

| Поле | Значение |
| --- | --- |
| Git-тег | `v0.1.0` |
| Заголовок GitHub Release | `zUI 0.1.0 Lyra` |
| ZIP для Windows | `zUI-x86_64-pc-windows-msvc.zip` |
| Файлы внутри ZIP | `zUI.exe`, `LICENSE` |

Не добавляйте имя к Git-тегу, Cargo-версии или имени исполняемого файла.
Номер должен оставаться пригодным для сравнения автообновлением; архив содержит
target, который использует GitHub-updater.

## Перед публикацией

Ниже обязательные проверки, пока **не выполненные автоматически** в этой подготовке:

- [ ] `cargo check --workspace --all-targets --locked`.
- [ ] `cargo test -p z-core -p z-i18n --locked`.
- [ ] `cargo run -p z-i18n --bin check-locales --locked`.
- [ ] Сборка Windows x64 в release-режиме.
- [ ] Первый запуск из чистой папки и запуск с настройками от 0.0.4.
- [ ] Избранное после перезапуска, поиск, фильтры и выбор нужной стратегии.
- [ ] Скролл над карточками и свободными боковыми полями.
- [ ] Скрытие в трей, открытие из трея, выход и оба запоминаемых действия.
- [ ] Возврат вопроса при закрытии через настройки.
- [ ] Новый экран изменений: RU/EN, светлая/тёмная тема, минимальный размер окна.
- [ ] Отсутствие профилей на главной.
- [ ] Установка/запуск Zapret и Telegram, тестирование стратегий и изменение/восстановление DNS.
- [ ] Обновление с предыдущего релиза из архива с указанным именем и структурой.
- [ ] В архиве есть LICENSE и нет runtime, настроек, журналов, секретов и отладочных символов.

## Сборка и упаковка

В PowerShell из корня проекта:

```powershell
cargo build --release --locked --target x86_64-pc-windows-msvc -p zUI --bin zUI
New-Item -ItemType Directory -Path dist -Force
Compress-Archive -LiteralPath @('target/x86_64-pc-windows-msvc/release/zUI.exe', 'LICENSE') -DestinationPath dist/zUI-x86_64-pc-windows-msvc.zip -Force
```

Затем проверьте архив, перенесите заметки из [CHANGELOG](../CHANGELOG.md) в тело
GitHub Release, создайте тег `v0.1.0` и приложите ZIP. Эти действия выполняются
после успешных проверок; эта подготовка не создаёт тег и не публикует релиз.

## Следующий выпуск

1. Измените числовую версию и при необходимости имя.
2. Синхронизируйте версии workspace-пакетов в Cargo.lock.
3. Обновите `whats-new-summary`, `whats-new-footer` и `whats-new-notes` во всех языках.
4. Сохраните формат заголовков `##` и пунктов `-` для карточек экрана изменений.
5. Обновите README, CHANGELOG и этот документ.
6. Выполните проверки выше.

Профили скрыты флагом `release::PROFILES_VISIBLE`. Отключение не удаляет
профили из Settings; возвращать их в интерфейс следует отдельным выпуском
после проверки сценариев применения.
